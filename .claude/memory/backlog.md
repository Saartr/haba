### Ручной лог не проверяет value, а синк — проверяет (найдено 2026-07, ещё актуально)

`POST /habits/:id/logs` (`backend/src/api/habits.js`, ~строка 368) валидирует только
`value === undefined`. Соседний `/logs/sync` рядом проверяет и тип, и диапазон:
`typeof value !== 'number' || value < 0 || value > 200000`.

**Чем это плохо:** групповые count-цели ранжируют участников по `entry_totals` (SUM), то есть
клиент может отправить любое число и возглавить таблицу. Нечисловое значение уронит запрос в 500.

**Как чинить:** перенести ту же проверку из `/logs/sync` в ручной эндпоинт. Верхнюю границу,
возможно, стоит взять другую — 200000 подобрана под шаги.

Найдено субагентом arch-integrity-review, который удалён 2026-09-10; проверено вручную, что
расхождение на месте.

### `.env` на сервере читается всеми пользователями (найдено 2026-09-11)

`/var/www/haba/backend/.env` лежит с правами `644`: секреты (`JWT_SECRET`, ключи VK, пароль
служебного входа) может прочитать любой локальный пользователь сервера. Процесс `step-bot`
работает от root, поэтому `chmod 600` ничего не сломает. Пользователю предложено, ответа не было.

### pm2-логи без ротации (найдено 2026-09-11)

`pm2-logrotate` не установлен, `/root/.pm2/logs/step-bot-out.log` растёт без ограничений (за две
недели ~170 КБ, в основном NOTICE миграций при каждом рестарте). Персональных данных там не
нашлось, так что не срочно. Но срок хранения этих логов не указан на странице удаления аккаунта —
если бэкенд начнёт писать туда данные пользователей, поставить ротацию и поправить страницу
([[feature-legal-pages]]).
