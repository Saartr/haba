Веб-версия того же кода (`expo export --platform web`), живёт на корне `https://apptapa.ru`.
Заработала 2026-08-30, вход через Яндекс проверен вживую.

## Что на вебе есть и чего нет

| | Веб |
|---|---|
| Вход через Яндекс ID | ✅ |
| Вход через VK ID | ❌ намеренно |
| Пуш-уведомления | ❌ |
| Health Connect и фоновый синк шагов | ❌ (аналога на вебе нет) |

**Почему VK нет:** у приложения VK ID (`54615454`) платформа жёстко Android и в консоли
не меняется. Веб потребовал бы отдельного приложения со своими App ID / Secure key /
Service token, потому что `secure.checkToken` проверяет токен против выдавшего приложения.
Решено не заводить. Серверная реализация веб-обмена для VK была в коммите `86ff9cc`.
Кнопка VK на вебе скрыта, на Android осталась.

## Как устроен вход

Нативный SDK на вебе недоступен, а Яндекс поддерживает только authorization code
(implicit-флоу у него нет вовсе). Поэтому:

1. `modules/yandex-id/index.web.ts` генерирует PKCE-пару, кладёт verifier и state в
   `sessionStorage` и уводит на `oauth.yandex.ru/authorize`
2. Яндекс возвращает на `https://apptapa.ru/auth/yandex/callback` (Redirect URI прописан
   в консоли, платформа «Веб-сервисы»)
3. `app/auth/yandex/callback.tsx` сверяет `state`, отдаёт код на сервер и сохраняет токены
4. `POST /auth/yandex/web` меняет код на токен провайдера **на сервере** (токен не попадает
   в JS страницы) и переиспользует `yandexSignIn` — ту же функцию, что и мобильный вход

Обмен идёт с PKCE, `client_secret` не нужен ни браузеру, ни серверу.

⚠️ Гвард в `app/_layout.tsx` уносит неавторизованных на `/welcome`. Маршрут `auth/*`
добавлен в исключения — иначе страницу callback уносит раньше, чем код успевает
обменяться, и вход молча откатывается на экран входа.

Токены на вебе — `localStorage` (`lib/auth.web.ts`): `expo-secure-store` там нет, как и
health-sync воркера, который в приложении ротирует refresh в фоне.

## Размещение

- Корень домена — статика из `/var/www/haba/web`, раздаёт nginx (`try_files $uri $uri.html
  $uri/index.html /index.html`)
- `/api`, `/join`, `/health` — отдельный location на Node; `/avatars/` и `/download/` — alias
- Страница со сборкой APK переехала на `/download/`; `/download` без слэша редиректится
  туда же (иначе проваливался в SPA)
- Выкладка: `./deploy-web.ps1` (собирает и переставляет каталог одним `mv`)
- `app/+html.tsx` — HTML-оболочка: заголовок вкладки, иконки, рамка по ширине

## Грабли, стоившие времени

- **Платформенные варианты модуля не подхватывались.** В `modules/yandex-id/package.json`
  было `"main": "index.ts"` — с расширением Metro резолвит файл напрямую и `index.web.ts`
  не видит, в веб-бандл попадала нативная версия. Нужно `"main": "index"`. Поле `browser`
  для этого НЕ годится: на нативе оно тоже участвует в резолве
  (`resolverMainFields = react-native, browser, main`) и уводит Android на веб-реализацию.
- **`expo-notifications` роняет всё приложение на вебе.** Модуль загружается, но
  `getLastNotificationResponse` не реализован — `useLastNotificationResponse` падает на
  первом рендере. try/catch «модуля нет» это не ловит. Guard по `Platform.OS !== 'android'`
  в `lib/notifications.ts` и на слушателе в `app/(tabs)/habit/[id].tsx`.
- **Вёрстка от ширины окна.** `useWindowDimensions`/`Dimensions.get('window')` в браузере
  дают ширину окна, и вёрстка вылезала за рамку на десктопе. Заведён `lib/layout.ts`:
  `WEB_MAX_WIDTH` (480) и `useContentWidth()` — на нативе ширина экрана, на вебе не больше
  рамки. Тем же числом ограничен `#root` в `+html.tsx`.

## Как проверять, что веб-работа не сломала Android

Пользователь требует, чтобы разработка веба не задевала приложение. Проверка — по
собранному бандлу (`npx expo export --platform android`), а не на глаз:

- **Сравнивать sha256 `.hbc` бесполезно** — компиляция Hermes невоспроизводима, две сборки
  одного кода дают разные хеш и размер. Сравнивать нужно **имя** бандла (это хеш
  JS-содержимого), список файлов и `metadata.json`.
- **Кириллицу в `.hbc` искать в UTF-16**, обычный grep её не находит и показывает ложные нули.
- Подстрочный поиск даёт ложные срабатывания на стыках строк в таблице Hermes — каждое
  совпадение смотреть по контексту.
- Веб-ветки в нативный бандл не попадают: Metro подставляет `Platform.OS` для целевой
  платформы и вырезает мёртвый код. `app/+html.tsx` в нативный граф не входит вообще.

**How to apply:** любую правку в общем коде ради веба закрывать `Platform.OS`-проверкой и
после сборки убеждаться, что в android-бандле нет веб-строк, а нужные (кнопки входа,
`YandexIdModule`) на месте.
