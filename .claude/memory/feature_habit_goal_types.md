## Статус на 2026-07-31: закоммичено (`3bd7ce4`), запушено на ревью в `mironovpeter10/ui-components`, коллегой ещё не смотрено

Три связанные правки по макетам Figma (Tapa App, `yTlBE7MQqQTvxez3UP4n48`), пользователь показывал по одной, для каждой были уточняющие вопросы — ответы см. ниже, они не всегда очевидны из макета.

### 1. Мастер создания цели — «С целью / Без цели» (шаг 2, `checkin_type: 'count'`)

`app/(tabs)/custom-habit/step2.tsx`: `SegmentedControl` «С целью»/«Без цели» под полем «Название единицы». «Без цели» — простой счётчик БЕЗ отметки о выполнении, поле «Цель» скрывается, `goal_value` уходит `undefined` → на бэке `NULL`. Работает и для solo, и для group (раньше «опционально» было только для группы).

Стейт: `CustomHabitState.hasGoal: boolean` (`custom-habit/_layout.tsx`, default `true`). Валидация в `handleNext()`: если `hasGoal` — цель обязательна и >0, иначе поле не проверяется вообще.

**Важно:** «без цели» для группового count УЖЕ существовало раньше (безлимитная групповая цель, см. [[feature-group-count-goal]]) — этот тоггл просто дал ему явный UI-переключатель на шаге создания вместо неявного «оставь пустым». Для solo это НОВЫЙ сценарий, раньше `goal_value` было обязательным для персональных count-целей.

### 2. `checkin_type: 'count'`, `goal_value == null` («без цели») — детальные экраны и карточка

Все три места читают `isCountNoGoal = checkin_type==='count' && goal_value==null` и завязаны на `lib/habit-status.ts` → `computeHabitStatus()`, которая вернула новые поля `showTag`/`showStreakRow` (false для count-без-цели).

- **Карточка в списке** (`HabitCard` в `index.tsx`) — без тега статуса (`showTag=false`), подпись «Сделано сегодня», значение «N раз» (`formatUnit(n, null)` — не показываем единицу измерения, которую пользователь выбрал на шаге 2, юзер явно попросил везде «раз», не «стакан»/«км»/что угодно).
- **`SoloHabitScreen`** — Неделя/Месяц тоггл (был только Неделя), месячный календарь БЕЗ красных точек (`CalendarWeek noMissIndicator`, `CalendarMonthly` без `missedDates`), карточка «Сделано сегодня: N раз» (без стрика — юзер явно попросил убрать, «без порога непонятно что считать стриком»), CTA «Я сделал» (+1) + карандаш-редактирование (только когда `todayLog.value>0`) → модалка add/replace.
- **`GroupHabitScreen`** — ОДНА секция «Все участники» (итоги `entry_totals` за всё время, не «Сегодня»+«Общая статистика» как раньше), та же кнопка «Я сделал»+карандаш. `MemberRow` (`shared.tsx`) получил проп `unit?: string|null` — но сейчас везде передаём `null` (тоже «раз», не единица).

### 3. `checkin_type: 'count'`, `goal_value != null` («с целью») — детальный экран (только Solo, макет node `1713-11090`)

Раньше: чипы «Сегодня»/«Неделя» переключали период просмотра суммы, заголовок «Персональный результат», карточки «Стрик»/«Максимальный». По макету:
- Чипы и заголовок **убраны**.
- Добавлен **Неделя/Месяц** тоггл (как у «без цели») — месячный календарь **С** красными точками (`missedDates` считаются от даты создания цели до вчера, дни без записи ≥ порога).
- Карточки **всегда про сегодня**: «{ед.} сегодня N/цель», «Стрик», «Лучший» (было «Максимальный» — переименовано под макет).
- CTA: **если за сегодня есть любая запись (value>0, даже не дотянувшая до цели)** → «Редактировать запись» (secondary, открывает модалку add/replace); иначе → «Внести {ед.}». Раньше кнопка «Внести» была всегда, независимо от наличия записи.

Group count-с-целью НЕ трогали — макета для этого случая не показывали.

### 4. Кастомная Да/Нет (`checkin_type: 'boolean'`) — обе (solo node `1712-10568`, group node `1714-11927`)

**Solo:** в неотмеченном состоянии кнопки были зелёная/красная без иконок («Выполнил»/«Не выполнил») — стали ОБЕ брендовые фиолетовые с иконками ✓/✕. **Только для кастомных целей** (`category` НЕ `smoking`/`no-smoking`) — готовая «Отказ от курения» осталась зелёной/красной (юзер explicitly подтвердил не трогать). Флаг `isSmoking` в `SoloHabitScreen`. Состояние «отмечено» (→ «Редактировать запись») не менялось, уже было верным.

**Group:** добавлен `isBoolCustom = checkin_type==='boolean' && category!=='steps'` — готовая групповая «Шаги» (тоже boolean под капотом) НЕ трогается, у неё свой флоу («Шагов сегодня», «Внести шаги»). Для кастомной группового Да/Нет:
- Неделя/Месяц тоггл + месячный календарь (мой результат, зелёные+красные — как у count-с-целью).
- Заголовок «Персональный результат» убран у boolean-ветки (у «Шагов» остался).
- **«Все участники» показывают текст «Выполнил»/«Не выполнил»** вместо числа — `MemberRow` получил проп `boolean?: boolean`.
- CTA: есть отметка за сегодня → «Редактировать запись» (новый стейт `editingBoolean`, был только у Solo); нет → две брендовые кнопки «✓ Выполнил»/«✕ Не выполнил» (раньше — одна кнопка «Отметить выполнение»/«Выполнено», зелёная при отметке).

### Побочные изменения инфраструктуры

- **`components/Button.tsx`** — новый `variant="icon"` (TapaDS node `55-7`, "Type=Icon only"): квадрат 56×56, радиус 12, рамка 2px `brand.primary` (pressed → `brand.pressed`, disabled → `neutral[300]`/иконка `neutral[600]`), заливка `c.surface.input`. Заменил самодельный `Pressable` с инлайновой функцией-стилем для карандаша-редактирования в Solo/Group — **та реализация не рендерила стиль вообще** (голая иконка без фона/рамки) на билде New Arch/Fabric: стиль на `Pressable` через `style={({pressed}) => ({...})}` молча игнорировался, хотя тот же стиль на вложенном `View` работал нормально. Если где-то ещё встретится «стиль не применяется, хотя бандл точно свежий» — проверить именно это (стиль на самом Pressable vs на дочернем View).
- **`lib/units.ts`** — новая `formatUnit(n, unit)`: счётная плюрализация (1/2-4/5+), для `unit=null` → «N раз», для пресетных единиц (`UNIT_FORMS` — Стакан/Час/Шаг/Литр и т.п.) → «N стаканов», для кастомных (не в словаре) — фолбэк на лейбл без склонения (форм для произвольных слов нет).
