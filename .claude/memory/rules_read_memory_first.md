Любой агент, работающий в этом репозитории, **сначала читает память, потом берётся за
задачу**. Не наоборот и не «по ходу дела».

**Why:** пользователь установил это правило явно (2026-08-30). В памяти лежат решения,
которые из кода не выводятся: почему Telegram-вход удалён (199-ФЗ), почему сервер переехал
в РФ (152-ФЗ), почему package остался `haba` при названии «Тапа», почему у веб-версии нет
входа через VK. Агент, начавший без этого, тратит время на переоткрытие уже принятых
решений и предлагает то, от чего осознанно отказались.

**How to apply:**

1. `.claude/memory/MEMORY.md` — индекс, он подгружается всегда. Начинать с него.
2. Открыть файлы по теме задачи: `rules_` — как здесь принято работать, `infra_` — стек,
   окружение, БД, `feature_` — конкретная фича, `ui_` — паттерны интерфейса,
   `backlog` — что уже решено отложить, `reference_` — внешние ресурсы.
   Часть файлов подгружается автоматически через `CLAUDE.md`, остальные — руками.
3. Проверять память и на «стоп-сигналы»: возможно, задача уже обсуждалась и по ней есть
   решение (например, [[rules-web-scope]] или пункты в [[backlog]]).
4. Память отражает состояние на момент записи. Если она называет файл, функцию или флаг —
   убедиться, что они ещё существуют, прежде чем на них опираться.
5. По ходу работы память **обновлять**, а не только читать: перед коммитом — актуализировать
   затронутые файлы (см. [[rules-git-workflow]]).
