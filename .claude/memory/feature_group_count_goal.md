Кастомная групповая цель типа «Количество» (`type='group'`, `checkin_type='count'`) может быть **безлимитной**: `goal_value = NULL`. Участник просто накапливает значение за день (одна строка `habit_logs` на юзера/день, «Добавить» математически увеличивает value — НЕ несколько записей). Реализовано 2026-07-03.

**Мастер создания** (`custom-habit/`):
- Шаг 2: для групповой count-цели поле «Цель» опционально («Оставь пустым — без ограничения»); для соло — обязательно, как раньше
- Шаг 3: периодичность `'any'` («Без ограничений») — без доп. полей; лейбл у SegmentedControl длительности — «Срок» (Бессрочно/Период/До цели)

**Бэкенд:**
- `GET /habits/:id` → `entry_totals` (Record userId → сумма value за всю историю цели)
- `GET /habits/:id/logs/day?date=` — значения всех участников за один день
- `POST /habits/:id/logs` для групповой count-цели шлёт пуш `notifyEntryAdded` при каждой записи — см. [[feature-push]] (пуш №5)
- `PATCH /habits/:id` сохраняет `goal_value`/`unit_preset`/`goal_unit` только если поле реально передано (иначе экран редактирования затирал их — был баг с пресетом шагов 7000)

**Экран цели** (`habit/[id].tsx`, ветка `checkin_type === 'count'`):
- Переключатель Неделя/Месяц у календаря (по умолчанию неделя); `CalendarWeek` с `noMissIndicator` — без красного «пропуска»: есть запись → зелёная галочка, нет → серый контур
- Тап по дню в месячном виде → BottomSheet со значениями каждого участника за день (`getHabitDayLogs`)
- Секция «Сегодня» (значение каждого участника за день) + «Общая статистика» (`entry_totals`, без «/цель»); Стрик/Максимальный НЕ показываются
- Кнопки: «+1 {единица}» (primary, мгновенный инкремент без модалки) + «Изменить {единица}» (secondary, модалка Добавить/Заменить)
- Текст кнопок склоняется через `lib/units.ts` (`pluralUnit`/`genitiveUnit`) от `goal_unit`
- На карточке главного экрана безлимитная цель всегда `done` (довольный Тапа), даже при 0 за день

**How to apply:** `checkin_type='count'` сейчас выставляется только мастером кастомных целей — пресеты («Шаги» и др.) имеют `'boolean'` по дефолту, поэтому ветка `checkin_type === 'count'` на экране цели фактически означает «кастомная count-цель». При добавлении дневного лимита к такой цели вся описанная логика продолжает работать (появится «/цель» у шагов-подобных карточек — см. тернарники `computeHabitStatus`).
