## Статус на 2026-07-09: редизайн влит в main (коммит `781ab8e`)

Главный экран заменён по новому макету Figma Tapa App (`yTlBE7MQqQTvxez3UP4n48`, node `1604-8280`), ветка `mironovpeter10/ui-components` влита fast-forward. Поверх редизайна в тот же день добавлено:
- **pull-to-refresh** списка целей (`RefreshControl`, брендовый цвет, кружок опущен `progressViewOffset={56}`) — тот же `load()`, что и focus-эффект, без полноэкранного лоадера
- **тени карточек и «простыни» убраны** (см. [[rules-design-system]] — `useCardShadow` удалён)
- фикс двойного тапа по карточке (`openingHabitRef`) и статус `done` для безлимитной групповой count-цели (`goal_value == null` → всегда довольный Тапа) сохранены в `computeHabitStatus`

⚠️ **Известная регрессия:** экран профиля (`/(tabs)/profile`, и через него `profile-settings` с «Обновить аватар») **недостижим из UI** — единственным входом был тап по аватару в старой шторке, а в новом дизайне ни Toolbar, ни app-settings на профиль не ведут. Ждёт решения (иконка в Toolbar / пункт в настройках / вариант из Figma).

**Why:** Пользователь показал новый макет — убрали шторку с аватаром/приветствием, вместо неё маскот+прогресс-бар+статус, карточки целей редизайнены (без иллюстраций-аватарок, плоские, с тегом статуса), FAB заменён на Toolbar.

### Известные хвосты / что проверить завтра

- **Позиционирование меню `Fab`** — при попытке сделать его надёжным через `Modal`+`measureInWindow` выяснилось, что `measureInWindow` в этом Dev Client окружении возвращает координаты, НЕ совпадающие с реальной позицией элемента (подтверждено визуальной отладкой красной линией). Откатили `Fab.tsx` к простой версии (без `Modal`, позиционирование `right:0`/`bottom:...` относительно локального родителя) — работает только когда `Fab`/`Toolbar` в угловой/центрированной абсолютной обёртке (как на главном экране). Подробности и попытки — см. [[backlog]].
- Пропорции шапки (140×113 маскот, отступы) реверс-инжинирены из макета, где сама иллюстрация была забагована (повёрнута на 180°, наезжала на текст) — не 100% точные, возможна донастройка по глазам после визуальной проверки.
- Правило «Максимальный стрик показывать где валидно» = моё решение (искл. progression и pullups), не сверено построчно с доп. примерами макета сверх исходных 7.
